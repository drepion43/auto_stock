# auto_stock 기획서 (PRD)

> 작성일: 2026-08-17 (4차 갱신: 리스크 관리 정책 전 항목 확정 — 제품/기획 레벨 논의 완료)
> 상태: 기획 완료 (Product-level Complete) — 남은 TBD는 모두 구현/기술 설계 단계에서 확정될 항목 (11절 참고)

## 1. 개요

`auto_stock`은 주식 시장 데이터를 분석해 매매를 추천하고, 사용자 승인을 거쳐 반자동으로 주문을 실행하는 개인용 트레이딩 자동화 시스템이다.

- **목적**: 처음에는 학습·전략 검증 목적으로 시작하되, 검증이 끝나면 실전 투자로 단계적으로 전환한다.
- **전환 로드맵**: 모의투자(paper trading) 환경에서 추천 로직과 리스크 관리 모델을 충분히 검증한 뒤에만 실전 자금 운용으로 넘어간다.

## 2. 범위 (Scope)

**포함**:
- 주식 추천 엔진 (기술적 지표 + ML/딥러닝 + LLM 차트 해석 + 뉴스/공시 분석)
- 추천 근거 설명(Explainability) — 왜 이 종목/타이밍인지 사람이 이해할 수 있는 언어로 제시
- 리스크 관리 / 포지션 사이징 모델 (1차 목표에서는 참고용 사이징 제안까지 — 아래 참고)
- 텔레그램/디스코드 봇을 통한 알림 인터페이스

**제외 (현재 단계)**:
- **반자동 주문 실행** — 1차 목표(추천까지)에서는 제외, 2차 목표로 이연 (§9 참고). 브로커 API 연동·크리덴셜 관리 없이 추천 엔진의 가치를 먼저 검증하기 위함
- 웹 대시보드 / 모바일 앱 (MVP 이후 확장 예정)
- 완전 자동 매매 (사람 승인 없는 주문 실행)
- 클라우드 상시 운영 (로컬 PC 검증 이후 단계)

**확정된 시장/유니버스**:
- 대상 시장: 국내 코스피/코스닥 + 나스닥(미국 주식)까지 확장
- 종목 유니버스: 전체 상장 종목 스캐닝 (섹터/지수 한정 없음)
- 스캔 주기: 장중 실시간에 가깝게 스캔 (구체 인프라 설계는 TBD, 8절 참고)
- 예산 규모: 소액 (수백만원대, 테스트 위주) — 6절 리스크 한도 설계의 근거

## 3. 핵심 사용자 흐름

```
1) 데이터 수집 (시세/차트/지표 + 관련 뉴스/공시)
        ↓
2) 추천 엔진이 매수/매도 후보 생성
   (기술적 지표 규칙 + ML 모델 + LLM 차트 해석 + 뉴스/공시 분석 결합)
        ↓
3) 리스크·포지션 사이징 모델이 추천에 대해 수량/한도 계산
        ↓
4) 추천 근거(어떤 지표·뉴스·패턴이 추천에 영향을 줬는지)를 자연어로 요약 생성
        ↓
5) 텔레그램/디스코드 봇으로 추천 내역 + 근거 설명 함께 전송
        ↓
6) 사용자가 승인 / 거부
        ↓ (승인 시)
7) 브로커 API를 통해 자동 주문 실행 (모의투자 우선)
        ↓
8) 체결 결과 및 포트폴리오 상태를 봇으로 알림
```

## 4. 시스템 아키텍처 개요

Python + LangChain `deepagents`(LangGraph 기반) 위에서 역할별 서브에이전트로 구성하는 것을 제안한다. `deepagents`는 격리된 컨텍스트를 갖는 서브에이전트, 파일시스템 툴, 스킬 로딩, 메모리/요약 미들웨어를 기본 제공하므로 아래와 같이 매핑할 수 있다.

| 서브에이전트 | 역할 |
|---|---|
| 차트분석/예측 에이전트 | 차트 데이터를 LLM에 입력해 패턴 해석 및 예측 시그널 생성 |
| 규칙엔진 | 이동평균, RSI, MACD 등 기술적 지표 기반 1차 필터링 |
| ML 예측 모듈 | 통계/딥러닝 모델 기반 가격·확률 예측 (규칙엔진·LLM 결과와 결합) |
| 뉴스/공시 분석 에이전트 | 종목 관련 기사·공시를 수집해 핵심 이벤트·감성(긍정/부정/중립)을 추출, 다른 계층의 시그널과 결합 |
| 리스크·포지션 사이징 에이전트 | 계좌 리스크 한도 내에서 매매 수량/비중 계산 |
| 추천 설명 생성기 | 규칙엔진·ML·LLM 차트해석·뉴스분석 결과를 종합해 사람이 이해할 수 있는 자연어 근거를 생성 (Explainability) |
| 주문 실행 에이전트 | 브로커 API 연동, 승인된 주문만 실행 |
| 알림/승인 봇 | 텔레그램/디스코드로 추천 내역 + 근거 설명 전송, 승인·거부 입력 수집 |

각 에이전트는 상위 오케스트레이터(메인 에이전트)가 조율하며, 주문 실행 에이전트는 반드시 사용자 승인 신호를 받은 이후에만 동작하도록 설계한다(반자동 원칙).

## 5. 추천 로직 설계 방향

- **규칙 기반 계층**: 이동평균/RSI/MACD 등 전통적 기술적 지표로 1차 후보군 필터링
- **ML/딥러닝 계층**: 해석 가능한 전통적 ML(scikit-learn 등)로 시작 → 검증 후 딥러닝으로 고도화한다. 소액 예산·전체 종목 실시간 스캔의 연산 부담·초기 단계 오버피팅 리스크를 고려할 때, 먼저 가볍고 설명 가능한 모델로 파이프라인을 검증한 뒤 성능이 확인된 부분만 딥러닝으로 교체하는 것이 안전하다 (구체 알고리즘/프레임워크 선정은 TBD)
- **LLM 계층**: 차트 데이터를 LLM에 입력해 패턴 해석 및 정성적 판단 보강
- **뉴스/공시 계층**: 종목에 영향을 줄 수 있는 기사·공시를 수집해 감성분석·핵심 이벤트 추출 후 시그널로 반영한다. 가격 데이터만으로는 알 수 없는 "왜 움직이는지"에 대한 정보 우위를 제공하며, 실적 서프라이즈·산업 이슈 등은 가격에 선행하는 경우가 많다 (데이터 소스는 7.2절 참고)
- 네 계층의 결과를 종합하는 앙상블/가중치 방식은 TBD — 백테스트를 통해 검증 필요
- **백테스트**: 실거래 전 반드시 5년 이상 장기 데이터로 백테스트해 전략 유효성을 검증한다 (데이터 소스는 7절 참고, 백테스트용 데이터 정합성 검증 방법은 TBD). 뉴스 계층은 과거 뉴스 아카이브 확보가 가격 데이터보다 까다로워 백테스트 반영 방법이 별도 TBD

### 5.1 설명가능성 (Explainability)

추천은 신호(매수/매도)만 전달하지 않고, 사용자가 승인 여부를 판단할 수 있도록 **근거를 함께 제시**한다.

- 규칙엔진(어떤 지표가 신호를 냈는지) + ML 모델(예측 확률/방향) + LLM 차트 해석(패턴 설명) + 뉴스/공시 분석(관련 이벤트·감성) 네 계층의 근거를 "추천 설명 생성기"가 종합해 2~3문장 수준의 자연어 요약으로 변환한다.
- 예시 형태: "OO전자: RSI 과매도 구간 진입 + 최근 실적 서프라이즈 기사 확인 + LLM 차트 분석상 단기 반등 패턴 감지. 예측 모델 신뢰도 XX%."
- 이 설명은 텔레그램/디스코드 승인 메시지에 함께 전송되어(3절 참고) 사용자가 승인/거부를 판단하는 근거가 된다.
- 구체적인 요약 템플릿·신뢰도 표기 방식은 TBD.

## 6. 리스크 관리 정책 초안

정교한 포지션 사이징/리스크 모델을 목표로 하며, 소액 예산(수백만원대) 기준 보수적으로 아래 한도를 모두 확정한다:

- **종목당 최대 투자 비중**: 계좌 자산의 5% 이내
- **최대 동시 보유 종목 수**: 10종목 (계좌 전체 최대 익스포저 50% — 나머지 50%는 항상 현금으로 보유해 변동성 완충 및 신규 기회 대응 여력 확보)
- **일일 최대 손실 한도**: 계좌 자산의 2% (도달 시 당일 자동매매 중단)
- **월간 최대 손실 한도**: 계좌 자산의 10% (도달 시 당월 자동매매 중단, 익월 재개)
- **손절매(Stop-loss) / 익절매(Take-profit) 기준**: 변동성(ATR) 기반 동적 기준 — 종목별 ATR(Average True Range)에 비례해 손절/익절 폭을 조정한다. 구체 ATR 배수(예: 손절 -1.5×ATR, 익절 +3×ATR 등)는 백테스트를 통해 확정 (TBD)
- **포지션 사이징**: 변동성(ATR) 기반 동적 조절 — 변동성이 낮은 종목은 종목당 한도(5%)에 가깝게, 변동성이 높은 종목은 더 적게 배분한다. 구체 계산식(예: 리스크 패리티 방식)은 기술 설계 단계에서 확정 (TBD)

> 손절/익절과 포지션 사이징 모두 ATR 기반으로 통일해 변동성 관리 로직의 일관성을 유지한다. 구체 배수·계산식은 백테스트 결과를 바탕으로 조정하는 것을 전제로 한다.

## 7. 브로커/데이터 연동 계획

### 7.1 브로커 구성

| 브로커 | 역할 | 조사 결과 |
|---|---|---|
| **토스증권 Open API** | 실전 전환 후 주 브로커 | 2026년 8월 정식 출시. 국내(KRX)+나스닥을 단일 통합 API로 지원, OAuth 2.0, 실시간 시세/일반주문/조건주문 제공. **모의투자(모의계좌) 연동 미지원 확정** — 공식 개발자 문서(`openapi.tossinvest.com/openapi-docs/overview.md`)에 sandbox/테스트 환경 언급이 전혀 없고, 공식 Q&A에서도 "별도 sandbox는 공개 안 됨. 실 환경에서 소액(1주)으로 테스트 권장. 모의계좌 기능은 토스증권 앱 내 모의투자 별도"라고 명시. Open API는 **실전계좌 전용**이며 앱 내 모의투자와는 완전히 분리되어 있음 |
| **한국투자증권 KIS Developers** | 모의투자 검증의 **필수 경로** | 모의투자 지원 확인됨. 국내+해외(나스닥 포함)+선물옵션을 하나의 API로 지원하는 성숙한 API |
| **키움증권 REST API** | 모의투자 검증의 **필수 경로** | 모의투자 지원 확인됨. 실전/모의 환경별로 앱키·시크릿을 별도 발급 |

**전략 (확정)**: 토스증권 Open API는 모의투자를 지원하지 않으므로, 추천·리스크·주문 실행 파이프라인 전체 검증은 **한투 또는 키움의 모의투자 API로만 가능**하다. 실전 전환 시에는 주 브로커를 토스증권으로 옮기되, 전환 초기에는 토스 공식 권장 방식대로 소액(1주 단위) 실거래로 API 자체(인증·주문·시세)를 먼저 검증한 뒤 점진적으로 비중을 늘린다.

### 7.2 데이터 소스

- **시세/차트 데이터**: 브로커 API에 의존하지 않고 별도 데이터 벤더(FinanceDataReader, pykrx 등)를 사용해 5년 이상의 백테스트용 과거 데이터 및 실시간 운영 데이터를 확보한다.
- **뉴스/공시 데이터** (조사 완료):
  - **DART 오픈API(전자공시시스템)** — 1순위 확정. 완전 무료, 개인 포함 누구나 인증키 신청만으로 이용 가능. 사업보고서·재무제표·주요사항보고서 등을 구조화 데이터(XML)로 제공.
  - **빅카인즈(BigKinds)** — 뉴스 소스 유력 후보. 무료 회원가입 기반, 1990년~현재 104개 매체 약 1억 건 뉴스 아카이브 보유, API로 검색·연관어·이슈 분석 제공. 단 API 자체의 rate limit·유료 티어 여부는 신청 시 재확인 필요 (TBD).
  - **GDELT** — 보조 후보. 무료·오픈이지만 한국어/국내 매체 커버리지가 상대적으로 약해 주 소스로는 부적합.

### 7.3 종목 스캐닝 및 실행 주기

- 전체 상장 종목을 대상으로 장중 실시간에 가깝게 스캔하는 것을 목표로 한다.
- 전체 종목 실시간 스캔은 연산량과 API 호출량 부담이 크므로, 배치 크기·호출 빈도·병렬화 전략은 기술 아키텍처 설계 단계에서 별도로 다뤄야 한다 (TBD).

## 9. MVP 정의 및 단계별 로드맵

- **MVP-0 (1차 목표, 지금 구현)**: 종목 추천까지만 — 규칙엔진 + 참고용 리스크·포지션 사이징 제안 + 추천 근거 설명 + 텔레그램/디스코드 알림. **주문 실행은 포함하지 않는다.** 브로커 API 연동·크리덴셜 관리 없이 추천 엔진의 핵심 가치를 먼저 검증하는 것이 목적
- **MVP-1 (2차 목표)**: MVP-0에 반자동 주문 실행을 추가 — 알림봇에 승인 흐름을 연결하고, 브로커 모의투자 API(한투/키움)로 승인된 주문 실행. 리스크 에이전트의 일일/월간 손실한도 자동중단 등 "집행" 로직도 이 단계에서 함께 구현
- **2단계**: 웹 대시보드 또는 앱으로 승인/모니터링 인터페이스 확장
- **3단계**: 검증된 전략에 한해 실전 투자로 전환

## 10. 리스크/규제 고려사항

- **증권사 API 이용약관** (조사 완료): 한국투자증권·키움증권 등은 애초에 "고객이 직접 프로그래밍한 알고리즘으로 본인 계좌를 매매"하도록 설계된 공식 서비스로, 개인 자동매매 자체는 정상적인 이용 범위다. 다만 시세 재배포·상업적 재판매 금지 등 구체 조항 원문은 이번 조사로 확인하지 못해, 가입 시 각 증권사 이용약관을 직접 재확인해야 한다 (TBD)
- **개인 알고리즘 매매 규제** (조사 완료, 법적 자문 아님): 파생상품(선물옵션) 알고리즘 거래는 한국거래소에 거래계좌 신고 의무가 있다 — 현재 프로젝트는 주식 중심이라 직접 해당 가능성은 낮으나, 추후 선물옵션으로 확장 시 유의 필요. 자동매매 "프로그램을 타인에게 판매/제공"하는 행위는 유사투자자문업으로 금융위 신고 대상이 될 수 있으나(자본시장법 101조 관련), 본 프로젝트는 본인 계좌 전용 개인 프로젝트라 해당 가능성은 낮다. 실제 신고 의무 여부는 변호사·금융당국(금융위/금감원) 확인이 필요하다
- **뉴스/공시 크롤링 저작권·약관 리스크**: 뉴스 사이트·포털의 콘텐츠를 무단으로 대량 수집하는 것은 저작권법·사이트 이용약관 위반 소지가 있다. DART, 빅카인즈 등 합법적 경로를 우선 사용하는 것으로 확정했다 (7.2절 참고)
- LLM 기반 매매 판단은 예측 오류·환각(hallucination) 가능성이 있으므로, 실전 전환 전 리스크 한도 및 사람의 최종 승인 절차를 유지해야 한다. 뉴스 감성분석 역시 오분류 가능성이 있어 단독 매매 트리거가 아닌 보조 시그널로만 사용한다
